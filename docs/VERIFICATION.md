# 验证记录

环境：Windows、Python 3.12.7、Node 22.17、Chrome headless。运行的是本机 SQLite 演示模式。

## 已执行

- GitHub Actions 首次主分支检查已在云端通过：依赖安装、后端测试、静态检查与前端构建。

- `python -m pytest tests -q`：30 项通过。
- `pytest tests --cov=app.lab --cov-report=term-missing`：上一轮 26 项测试的领域模块语句覆盖率 88%（包含模型、schema、API、服务、worker 和演示种子；不代表全部项目覆盖率，也不是分支覆盖率）。
- 并发：8 个线程同时预约同一设备同一时段，1 个成功，7 个 409；这是一致性测试，不是 QPS 测试。
- 幂等重试、同键不同请求、相邻时段、跨实验室越权、不能自审、不能提前领用、重复状态操作、故障取消和通知、站内通知去重、失败退避及人工重试。
- HTTP：登录、权限、设备新增及停用、预约状态变更、成员创建、通知归属、CSV 导出、审计与健康检查。
- TypeScript 严格类型检查和 Vite 生产构建通过。
- Ruff F 规则通过（仅检查活动模块，不将遗留模板文件计入）。
- Alembic 新库升级与 `alembic check` 通过，未检测到活动模型和迁移结构差异。
- Playwright + Chrome：成员登录并申请 → 退出 → 管理员登录并审批 → 成员登录并取消；检查 5 个成员手机页面无横向溢出、无 JS 页面错误。

## 复现说明

业务测试使用临时独立数据库，不写入演示库。浏览器验收会在合成演示库留下带“浏览器验收”前缀的已取消预约，便于确认流程确实产生了记录；不是业务用户数据。

禁止把测试通过写成“系统不存在竞态/安全问题”。新增接口、数据库或角色后，必须补测对应边界。

本轮增加个人资料持久化、邮箱变更密码验证、角色字段不可注入及全量已读账号隔离测试。浏览器验证头像键盘/点击入口、资料保存后头像更新、全部已读后禁用按钮和手机弹窗；界面写请求用拦截响应验证，真实持久化由独立临时数据库测试覆盖。
