# 求职展示指南

可以使用的表述（须本人理解并能复现）：

> 基于 FastAPI 官方模板开发实验室资源协作平台，完成设备预约、审批、领用归还及报修闭环；实现实验室范围和角色权限校验、幂等提交、事务化冲突检查及 Outbox 站内通知。通过并发测试验证 8 个重叠预约请求仅一个成功。

不能写：从零实现全栈框架、真实高校生产落地、十万 QPS、分布式锁保障高并发、外部消息 exactly-once。PostgreSQL 代码和部署配方尚未实测，不能当作已验证业绩。

准备回答：

1. 为什么不能先查询空闲再普通插入？用两个并发事务复现。
2. SQLite 写锁与 PostgreSQL 设备行锁有什么差异？哪些性能结论不能相互外推？
3. 幂等键作用域为什么是用户？同键不同请求为什么返回冲突？
4. 为什么待审批占用时段？如何避免长时间占用？24 小时过期规则有什么代价？
5. 为什么不能相信前端隐藏按钮？如何阻止猜测其他实验室的设备 ID？
6. 数据写入成功但通知失败怎么办？Outbox 如何减少双写不一致？
7. 为什么不能把逾期设备自动标成已归还？
8. 如何保证维修关闭一个故障后，其他未处理故障不会被忽略？
9. 哪些代码复用上游，哪些是自己新增？
10. 下一步先补哪种测试？优先真实 PostgreSQL 和开放部署安全，而非继续增加页面特效。

建议演示时保留失败场景：冲突、越权、错误时间窗口都应返回清晰错误。能解释拒绝条件，比只演示成功页面更有价值。
